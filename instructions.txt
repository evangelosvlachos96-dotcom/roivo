## Key concepts

For each concept, give a one-paragraph explanation followed by a 
"where to look" pointer to real code.

### Tenancy
The whole system is multi-tenant. Every business-level entity carries 
TenantId. ITenantContext gives the current tenant. Query filters apply 
tenant scope automatically. Raw SQL must apply it manually.

**Where to look:** 
- `src/Roivo.Application/Abstractions/ITenantContext.cs`
- `src/Roivo.Infrastructure/Persistence/ApplicationDbContext.cs` 
  (HasQueryFilter setup)
- `src/Roivo.Infrastructure/Persistence/Repositories/InvoiceQueryRepository.cs` 
  (raw SQL tenant filter example)

### Tenant types and permissions
Two tenant types: Accountant and Business. Permissions live in 
BusinessPermissions (static class). Handlers check permissions before 
loading entities.

**Where to look:**
- `src/Roivo.Core/Domain/[wherever]/TenantType.cs` (verify path)
- `src/Roivo.Application/Permissions/BusinessPermissions.cs` (verify path)
- Any handler — e.g. UpdateBusinessHandler.cs — shows the pattern

### Command/Query handlers
We use CQRS without MediatR. Each handler is a sealed class registered 
in DI. Blazor pages and Razor Pages inject handlers directly and call 
Handle(...). No reflection-based dispatch.

**Where to look:**
- `src/Roivo.Application/Configuration/ApplicationServiceCollectionExtensions.cs` 
  (DI registration)
- Any handler — e.g. CreateBusinessHandler.cs — shows the pattern

### Result types (discriminated unions)
Handlers return result types like CreateBusinessResult with variants 
Success, Forbidden, NotFound, DuplicateAfm. Callers pattern-match on 
result variant rather than catching exceptions.

**Where to look:**
- Any result file — e.g. CreateBusinessResult.cs — shows the pattern

### Validation order in handlers
Standard order: null-guard → permission → load → existence → 
business-rules → mutate → save → audit → return.

**Where to look:**
- `docs/CODING_STANDARDS.md` (section: Handler structure)
- Any handler — e.g. DeactivateBusinessHandler.cs

### Encrypted credential storage
AADE credentials stored encrypted via DataProtection API. Tenant-scoped 
keys. IAadeCredentialStore abstracts retrieval; EncryptedAadeCredentialStore 
implements it.

**Where to look:**
- `src/Roivo.Application/Abstractions/Aade/IAadeCredentialStore.cs`
- `src/Roivo.Infrastructure/Aade/EncryptedAadeCredentialStore.cs` 
  (verify path)

### Audit logging
AuditAction enum (numeric ranges per domain: auth 0-99, businesses 100-199, 
AADE 200-299). Written AFTER successful actions only.

**Where to look:**
- `src/Roivo.Core/Domain/Auditing/AuditAction.cs`
- `src/Roivo.Application/Abstractions/IAuditWriter.cs`

### Hangfire jobs
Recurring background jobs registered in Program.cs. Currently: 
NightlyAadeSyncJob (3 AM Athens) and AadeFailureNotificationJob (9 AM Athens). 
Hangfire dashboard at /hangfire shows their status.

**Where to look:**
- `src/Roivo.Web/Program.cs` (Hangfire setup section)
- `src/Roivo.Infrastructure/Jobs/AadeFailureNotificationJob.cs`
- Wherever NightlyAadeSyncJob lives

### Resilience
Polly retries on transient failures in HTTP clients. Result types 
express different failure categories. Business entity tracks 
HasAadeFailure / AadeLastFailureAt for credential failures.

**Where to look:**
- `docs/RESILIENCE_PATTERNS.md`
- `src/Roivo.Aade/AadeHttpClient.cs` (FetchAndParseAsync — sees 429, 
  401/403, etc.)

## Where to add new things

When adding a new feature, where does code go? Quick reference:
- New entity → Roivo.Core/Domain/Entities/
- New handler → Roivo.Application/Features/<Aggregate>/Commands or Queries/
- New abstraction (interface) → Roivo.Application/Abstractions/
- New repository implementation → Roivo.Infrastructure/Persistence/Repositories/
- New page → Roivo.Web/Components/Pages/
- New Greek string → Roivo.Resources/
- New migration → automatic via `dotnet ef migrations add`
- New test → tests/Roivo.<Project>.Tests/

### Trigger
User on /businesses/{id}/aade clicks "Συγχρονισμός τώρα" button.

### Files involved (in order)

   method. Calls SyncBusinessInvoicesHandler via injected dependency.
2. **src/Roivo.Application/Features/Aade/Commands/SyncBusinessInvoices/SyncBusinessInvoicesCommand.cs** 
   — the command record (just BusinessId).
3. **src/Roivo.Application/Features/Aade/Commands/SyncBusinessInvoices/SyncBusinessInvoicesHandler.cs** 
   — the orchestrator. Validates permission, loads business, fetches 
   credentials, calls AADE client, persists results.
4. **src/Roivo.Application/Permissions/BusinessPermissions.cs** — 
   `CanSyncAadeFor(tenantType)` returns true if the tenant can sync.
5. **src/Roivo.Infrastructure/Persistence/Repositories/BusinessRepository.cs** 
   — `GetByIdActiveOnlyAsync` loads the business if active.
6. **src/Roivo.Infrastructure/Aade/EncryptedAadeCredentialStore.cs** 
   (verify path) — decrypts userId + subscription key.
7. **src/Roivo.Aade/AadeHttpClient.cs** — `FetchInvoicesAsync` issues 
   two parallel HTTP GETs to AADE.
8. **AADE myDATA API** — returns XML responses.
9. **src/Roivo.Aade/AadeHttpClient.cs** — `ParseIncomingInvoices` and 
   `ParseOutgoingBookEntries` extract data from XML into DTOs.
10. **SyncBusinessInvoicesHandler** continues — upserts via 
    IInvoiceRepository and IIncomeBookEntryRepository, advances marks 
    on Business, optionally records failure state.
11. **src/Roivo.Infrastructure/Persistence/ApplicationDbContext.cs** 
    — SaveChangesAsync persists everything.
12. **src/Roivo.Application/Abstractions/IAuditWriter.cs** implementation 
    — writes AuditAction.AadeSyncCompleted entry.
13. Handler returns SyncBusinessInvoicesResult.Success — back to Blazor 
    page, which refreshes UI state.
