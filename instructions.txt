HOLISTIC REFACTOR: Introduce Roivo.Application layer with feature-based CQRS handlers.

CONTEXT:
We're moving from a fat-component architecture to a properly layered one. Business logic currently lives in Razor components (Roivo.Web/Components/Pages/Businesses.razor, BusinessCreate.razor, BusinessEdit.razor). This refactor extracts that logic into a new Roivo.Application project organized by feature, with CQRS-style command/query handlers.

This is purely structural. No new features, no behavior changes. End state: same smoke tests pass, but the code is dramatically more testable and maintainable.

ARCHITECTURE DECISIONS (locked, do not deviate):

- Lightweight pure-domain: entities stay in Roivo.Core. Core has ZERO references to EF Core or Microsoft.EntityFrameworkCore.* packages. Entity configurations live in Roivo.Infrastructure/Persistence/Configurations/ (already do).
- Feature-based folders in Application: Features/Businesses/, Features/Tenants/ (later), etc.
- CQRS via handler classes, NO MediatR. Each command/query has its own handler class. Razor components inject and call handlers directly.
- Result types: each command/query returns a discriminated union — abstract record + sealed inner records.
- Repository interfaces live in Roivo.Application/Abstractions/. Implementations live in Roivo.Infrastructure.
- ITenantContext moves to Roivo.Application/Abstractions/ITenantContext.cs (it's used by both Application and Infrastructure).

DEPENDENCY FLOW (enforce strictly):
- Roivo.Core ← references nothing (pure entities + validators)
- Roivo.Application ← references Roivo.Core only
- Roivo.Infrastructure ← references Roivo.Core + Roivo.Application (to implement Application's abstractions)
- Roivo.Web ← references all three (for DI registration and component injection)

The unusual one: Infrastructure references Application. This is correct — Application defines the abstractions (interfaces), Infrastructure provides the implementations. This is the Dependency Inversion Principle.

File: CreateBusinessHandler.cs

```csharp
namespace Roivo.Application.Features.Businesses.Commands.CreateBusiness;

using Roivo.Application.Abstractions;
using Roivo.Core.Domain.Entities;
using Roivo.Core.Domain.Validation;

public sealed class CreateBusinessHandler
{
    private readonly IBusinessRepository _repository;
    private readonly IAuditWriter _audit;
    private readonly ITenantContext _tenant;

    public CreateBusinessHandler(
        IBusinessRepository repository,
        IAuditWriter audit,
        ITenantContext tenant)
    {
        ArgumentNullException.ThrowIfNull(repository);
        ArgumentNullException.ThrowIfNull(audit);
        ArgumentNullException.ThrowIfNull(tenant);

        _repository = repository;
        _audit = audit;
        _tenant = tenant;
    }

    public async Task<CreateBusinessResult> Handle(CreateBusinessCommand command, CancellationToken cancellationToken = default)
    {
        ArgumentNullException.ThrowIfNull(command);

        var afm = (command.Afm ?? string.Empty).Trim();
        var name = (command.Name ?? string.Empty).Trim();

        if (!AfmValidator.IsValid(afm))
            return new CreateBusinessResult.InvalidAfm();

        // Check active duplicate first — that's a hard block.
        if (await _repository.AfmExistsAsync(afm, activeOnly: true, excludeId: null, cancellationToken))
            return new CreateBusinessResult.ActiveDuplicate(afm);

        // Check inactive duplicate — surfaces a reactivation option to the caller.
        var inactive = await _repository.FindByAfmAsync(afm, activeOnly: false, cancellationToken);
        if (inactive is not null && !inactive.IsActive)
        {
            return new CreateBusinessResult.InactiveDuplicate(inactive.Id, inactive.Name, inactive.Address);
        }

        var business = new Business
        {
            Name = name,
            Afm = afm,
            Kad = string.IsNullOrWhiteSpace(command.Kad) ? null : command.Kad.Trim(),
            Address = string.IsNullOrWhiteSpace(command.Address) ? null : command.Address.Trim()
            // TenantId is set by ApplicationDbContext.SaveChangesAsync override
        };

        await _repository.AddAsync(business, cancellationToken);
        await _repository.SaveChangesAsync(cancellationToken);

        await _audit.WriteAsync(
            action: "BusinessCreated",
            tenantId: _tenant.CurrentTenantId,
            entityType: nameof(Business),
            entityId: business.Id.ToString(),
            details: new { business.Name, business.Afm },
            cancellationToken: cancellationToken);

        return new CreateBusinessResult.Success(business.Id);
    }
}
```

Step 2.3 — UpdateBusiness feature

Following the same pattern, create:
- UpdateBusinessCommand: Id, Name, Afm, Kad, Address
- UpdateBusinessResult: Success, InvalidAfm, NotFound, ActiveDuplicateAfm
- UpdateBusinessHandler: load business via repository (active only), validate AFM, check duplicate (excluding self), apply changes (only fields that actually changed), save, audit log "BusinessUpdated" with from/to diff for changed fields only (no diff = no audit entry).

Step 2.4 — DeactivateBusiness feature

- DeactivateBusinessCommand: Id
- DeactivateBusinessResult: Success, NotFound, AlreadyInactive
- DeactivateBusinessHandler: load by Id (active only filter), set IsActive=false, save, audit "BusinessDeactivated" with Name + Afm snapshot.

Step 2.5 — ReactivateBusiness feature

- ReactivateBusinessCommand: Id, Name, Kad, Address (the new values the user typed during the reactivation flow)
- ReactivateBusinessResult: Success, NotFound, AlreadyActive, ConflictsWithActive (if another active business has same AFM somehow)
- ReactivateBusinessHandler: load by Id (any active state), check it's inactive, check no active business has the same AFM, apply name/Kad/Address from command, flip IsActive=true, save, audit "BusinessReactivated".

Step 2.6 — GetBusinessById query

- GetBusinessByIdQuery: Id, ActiveOnly (bool, default true)
- GetBusinessByIdHandler: returns Business? — repository call directly.
- No Result type — null indicates not found. This is a simple read, no business outcomes.

Step 2.7 — ListActiveBusinesses query

- ListActiveBusinessesQuery: no parameters (tenant scope is automatic).
- ListActiveBusinessesHandler: returns IReadOnlyList<Business> from repository.

Step 5.3 — Update docs/CODING_STANDARDS.md

Append a new section:

```markdown
## Layered architecture

Strict dependency flow:

Roivo.Core → no references
Roivo.Application → Roivo.Core only
Roivo.Infrastructure → Roivo.Core + Roivo.Application (implements abstractions)
Roivo.Web → all three

### What lives where

**Roivo.Core**
- Domain entities (Business, Tenant, BankAccount, etc.)
- Value objects (Currency enum, etc.)
- Domain validators (AfmValidator)
- Domain interfaces (ITenantScoped)
- NO EF Core. NO infrastructure concerns.

**Roivo.Application**
- Features/{Domain}/Commands/{ActionName}/ — Command + Handler + Result trio
- Features/{Domain}/Queries/{QueryName}/ — Query + Handler trio
- Abstractions/ — repository interfaces, infrastructure-facing interfaces
- Common/ — shared base types

Features are organized vertically. Working on businesses? Everything in Features/Businesses/. Working on auth? Features/Auth/.

**Roivo.Infrastructure**
- Persistence/ApplicationDbContext.cs
- Persistence/Configurations/ — IEntityTypeConfiguration<T> classes
- Persistence/Repositories/ — implementations of Roivo.Application.Abstractions interfaces
- Auditing/AuditWriter.cs
- Identity/HttpTenantContext.cs, TenantClaimsPrincipalFactory.cs
- External integrations (later: AADE, PSD2)
- EF Core lives ONLY here.

**Roivo.Web**
- Razor components and Razor Pages
- DI registration in Configuration/ extensions
- Components inject handlers from Application, NOT repositories or DbContext
- Components are thin: render UI, call handlers, map result to UI state

### Component discipline rules

A Razor component must not:
- Import Microsoft.EntityFrameworkCore
- Import Roivo.Infrastructure
- Inject DbContext, DbContextFactory, or any repository
- Call SaveChangesAsync, Add, Update, etc.
- Serialize JSON for audit logging
- Use System.Text.Json directly

A Razor component should:
- Inject command/query handlers
- Build commands/queries from form input
- Pattern-match on result types to determine UI behavior
- Stay focused on rendering and user interaction
```
