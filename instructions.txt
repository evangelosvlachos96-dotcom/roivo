### Domain context (read carefully — this informs every decision)

Roivo is a Greek B2B SaaS for cashflow intelligence. M4 connects to AADE myDATA, the Greek tax authority's invoice API. Users connect their AADE credentials (user_id + subscription_key) to their Business records. Nightly background sync pulls their invoices and stores them in our Invoices table.

Key facts about AADE myDATA:
- Two environments: mydata-dev.azure-api.net (dev/test) and mydatapi.aade.gr (production)
- For M4 we point at the DEV environment only — production is later
- Auth headers: aade-user-id (the user ID) and Ocp-Apim-Subscription-Key (the key)
- Responses are XML, not JSON. Use System.Xml.Linq for parsing.
- Key endpoints we use:
  - RequestDocs — fetch invoices issued TO this AFM (incoming)
  - RequestMyIncome — fetch invoices issued BY this AFM (outgoing)
  - We pull both per business and store them with a Direction enum (Incoming/Outgoing)
- Greek time (Europe/Athens) at the AADE side; we store UTC internally
- Document types: AADE uses code strings like "1.1" (sales invoice), "2.1" (services invoice), etc. We store the code as-is plus a human-readable name from a lookup table.

Architecture decisions (locked):
- New project: Roivo.Aade (already scaffolded as empty stub — fill it in)
- Application layer defines IAadeClient, IAadeCredentialStore abstractions
- Roivo.Aade implements them
- Hangfire schedules the nightly cron and on-demand jobs
- ASP.NET Core Data Protection API for encrypting subscription keys at rest
- AFM mismatch (credentials return data for a different AFM than the business has) → BLOCK the connection, force user to fix the business AFM or re-enter credentials. No partial-allow path in M4.
- Rate-limit credential validation: max 5 attempts per business per hour (anti-enumeration)

Roivo.Application already has full CQRS structure from M3. M4 adds the Aade feature folder following the same pattern.

    public sealed record BusinessNotFound : ConnectAadeResult;
    public sealed record Forbidden(string Reason) : ConnectAadeResult;
    public sealed record RateLimited : ConnectAadeResult;
    public sealed record InvalidCredentials : ConnectAadeResult;
    public sealed record AfmMismatch(string BusinessAfm, string CredentialsAfm) : ConnectAadeResult;
    public sealed record AadeUnavailable(string Message) : ConnectAadeResult;

ConnectAadeHandler flow:
1. Null-guard all deps (constructor injects IBusinessRepository, IAadeClient, IAadeCredentialStore, IAadeRateLimiter, IAuditWriter, ITenantContext).
2. Load business via IBusinessRepository.GetByIdActiveOnlyAsync — null → BusinessNotFound.
3. Permission check: only Accountants can connect AADE for any business; Business tenants can only connect for their own primary business. Add this rule to BusinessPermissions.cs in Core:
```csharp
   public static bool CanManageAadeFor(TenantType tenantType) => true; // Both can, but UI restricts business tenants to their primary
```
4. Try acquire rate limit slot via IAadeRateLimiter — if denied → RateLimited.
5. Call IAadeClient.ValidateCredentialsAsync — handle each variant. Return matching result on failure.
6. On validation Success: compare AFM returned by AADE vs business.Afm. If mismatch → AfmMismatch result.
7. Store credentials via IAadeCredentialStore.StoreAsync.
8. Audit log: "AadeConnected" with business name, AFM, and (importantly) NOT the credentials.
9. Return Success.

DisconnectAadeHandler:
- Loads business, checks permission, calls IAadeCredentialStore.ClearAsync, audits, returns Success/NotFound.

SyncBusinessInvoicesHandler:
- Loads business and credentials. If no credentials → NotConnected result variant.
- Calls IAadeClient.FetchInvoicesAsync with business.LastAadeSyncAt as `sinceUtc`.
- On Success: persists Invoice entities (upsert by AadeMark — the Mark is the unique key). Sets business.LastAadeSyncAt = DateTime.UtcNow.
- Audits run: "AadeSyncCompleted" with counts of new/updated invoices.
- Result variants: Success(int newCount, int updatedCount), NotConnected, NetworkError, AadeServerError.

GetAadeConnectionStatusHandler:
- Returns: IsConnected, LastSyncAt, MaybeUserIdMasked (first 4 chars + ***).

ListConnectedBusinessesHandler:
- Returns all businesses with credentials connected, used by the nightly cron job.

Create src/Roivo.Aade/AadeHttpClient.cs implementing IAadeClient:
- Constructor injects HttpClient (named "Aade"), IOptions<AadeSettings>, ILogger
- ValidateCredentialsAsync: GET /RequestMyIncome with minimal date range, parse response — if 200 + valid XML, extract AFM from response, return Success. If 401 → InvalidCredentials. If 5xx → AadeServerError. If timeout/network → NetworkError.
- FetchInvoicesAsync: makes two calls in parallel — RequestMyIncome (outgoing) and RequestDocs (incoming). Parse XML to AadeInvoiceDto list. Return Success.

XML parsing — use System.Xml.Linq. AADE's response structure (simplified):
```xml
<RequestedDoc>
  <invoicesDoc>
    <invoice>
      <issuer><vatNumber>...</vatNumber></issuer>
      <counterpart><vatNumber>...</vatNumber><name>...</name></counterpart>
      <invoiceHeader>
        <issueDate>2024-01-15</issueDate>
        <invoiceType>1.1</invoiceType>
        <currency>EUR</currency>
      </invoiceHeader>
      <invoiceSummary>
        <totalGrossValue>1240.00</totalGrossValue>
      </invoiceSummary>
      <mark>400001234567890</mark>
    </invoice>
  </invoicesDoc>
</RequestedDoc>
```

Store the full raw XML of each invoice in AadeInvoiceDto.RawXml for forensics.

Register HttpClient with Polly for retries in Roivo.Aade/Configuration/AadeServiceCollectionExtensions.cs:
```csharp
services.AddHttpClient("Aade", client =>
{
    client.BaseAddress = new Uri(settings.BaseUrl);
    client.Timeout = TimeSpan.FromSeconds(settings.TimeoutSeconds);
})
.AddPolicyHandler(GetRetryPolicy(settings.MaxRetries));
```

Where GetRetryPolicy uses Polly with exponential backoff: retry on 5xx and network failures only (NOT on 401/403 — those are credential errors).

Create src/Roivo.Aade/EncryptedCredentialStore.cs implementing IAadeCredentialStore:
- Constructor injects IDataProtectionProvider, IDbContextFactory<ApplicationDbContext>, ILogger
- Creates an IDataProtector with purpose "Roivo.Aade.Credentials"
- StoreAsync: encrypts userId AND subscriptionKey, stores both encrypted strings on the Business entity in fields AadeUserIdEncrypted and AadeSubscriptionKeyEncrypted. The current AadeUserId field needs to be renamed to AadeUserIdEncrypted in a migration.
- RetrieveAsync: loads business, decrypts both, returns AadeCredentials. Returns null if either field is null.
- ClearAsync: sets both encrypted fields to null on the business.
- HasCredentialsAsync: checks if both fields are non-null.

Create src/Roivo.Aade/InMemoryAadeRateLimiter.cs implementing IAadeRateLimiter:
- Uses IMemoryCache to track validation attempts per businessId
- 5 attempts per hour ceiling
- Returns false if ceiling exceeded
- Note: in-memory means it resets on app restart — for M4 this is fine, document the limitation. Distributed rate limiting via Redis is later.md.

NightlyAadeSyncJob.cs:
