Standing instruction for all future code generation (carry forward indefinitely):
Constructor null-guards: Every constructor in service classes, factories, repositories, and any DI-injected class MUST validate non-nullable reference-type parameters with ArgumentNullException.ThrowIfNull(paramName); at the top of the constructor body, BEFORE field assignment. Order:
csharppublic class SomeService(IDep1 dep1, IDep2 dep2) // ← don't use primary constructors for services
NO. Always:
csharppublic class SomeService : ISomeService
{
    private readonly IDep1 _dep1;
    private readonly IDep2 _dep2;

    public SomeService(IDep1 dep1, IDep2 dep2)
    {
        ArgumentNullException.ThrowIfNull(dep1);
        ArgumentNullException.ThrowIfNull(dep2);

        _dep1 = dep1;
        _dep2 = dep2;
    }
}
Primary constructors are OK for: simple DTOs, records, value objects without methods. NOT for services, factories, anything DI-injected.
Comments policy:

Add a why comment when code looks surprising, has a regulatory/security reason behind it, or compensates for an external system's quirk. Examples of when to comment:

Anti-enumeration in auth flows
AADE-specific data quirks (leading zeros, encoding, etc.)
Multi-tenant isolation enforcement
Race-condition handling
Workarounds for library bugs
Non-obvious algorithm choices


Add XML doc comments (/// <summary>) to: public interfaces, public services, public validators, public types in Roivo.Core and Roivo.Infrastructure that cross project boundaries.
Do NOT add comments that restate what the code obviously does. No "increment counter," "loop through items," "return result."
Use Greek for user-facing strings (error messages, UI labels). Use English for code comments and XML docs.
