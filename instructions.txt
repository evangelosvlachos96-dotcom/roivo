Add AADE connection health tracking to detect when credentials stop working, show user-facing banner immediately, and send email after 24+ hours of failure.

### Background

The resilience patterns doc identified that we detect AFM mismatch (specific case) but not general credential failure beyond a log line. Customer experience: sync silently fails, user doesn't know why invoices stopped arriving.

Solution: track failure state on Business entity, show banner in UI when broken, email user via Hangfire job if broken >24 hours.

### Task 1: Add failure tracking fields to Business

In src/Roivo.Core/Domain/Entities/Business.cs, add three properties:

```csharp
public bool HasAadeFailure { get; private set; }
public DateTime? AadeLastFailureAt { get; private set; }
public string? AadeLastFailureReason { get; private set; }
public DateTime? AadeFailureEmailSentAt { get; private set; }
```

The `AadeFailureEmailSentAt` tracks when we last sent the 24-hour notification email. Prevents duplicate emails — we only send once per failure period.

Add domain methods:

```csharp
/// <summary>
/// Records that an AADE sync attempt failed. The reason is a short string 
/// identifying the failure category (e.g., "InvalidCredentials", "AfmMismatch", 
/// "NetworkError") for UI messaging purposes.
/// </summary>
public void RecordAadeSyncFailure(string reason)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(reason);
    
    // Only update timestamp if this is a new failure (not a repeat).
    // We want AadeLastFailureAt to reflect when the failure STARTED, 
    // not the most recent failure attempt — so the 24-hour clock 
    // measures elapsed broken time.
    if (!HasAadeFailure)
    {
        AadeLastFailureAt = DateTime.UtcNow;
    }
    
    HasAadeFailure = true;
    AadeLastFailureReason = reason;
}

/// <summary>
/// Clears the AADE failure state. Called when sync succeeds OR when 
/// the user disconnects/reconnects credentials.
/// </summary>
public void ClearAadeSyncFailure()
{
    HasAadeFailure = false;
    AadeLastFailureAt = null;
    AadeLastFailureReason = null;
    AadeFailureEmailSentAt = null;  // Reset so a future failure can re-trigger email
}

/// <summary>
/// Marks that we've sent the 24-hour failure notification email. 
/// Prevents duplicate emails for the same continuous failure period.
/// </summary>
public void RecordAadeFailureEmailSent()
{
    if (!HasAadeFailure)
        throw new InvalidOperationException("Cannot record email sent — no active failure.");
    
    AadeFailureEmailSentAt = DateTime.UtcNow;
}
```

### Task 4: Wire failure detection in SyncBusinessInvoicesHandler

In src/Roivo.Application/Features/Aade/Commands/SyncBusinessInvoices/SyncBusinessInvoicesHandler.cs:

The handler currently routes on AadeFetchResult variants. Add failure tracking:

- On `AadeFetchResult.InvalidCredentials`: call `business.RecordAadeSyncFailure("InvalidCredentials")`, save, return existing result variant
- On `AadeFetchResult.AfmMismatch`: call `business.RecordAadeSyncFailure("AfmMismatch")`, save, return existing variant
- On `AadeFetchResult.NetworkError` or similar transient: do NOT mark as failure (transient errors aren't credential problems). Just log and return existing variant.
- On `AadeFetchResult.AadeServerError`: do NOT mark (also transient — AADE's problem, not ours).
- On `AadeFetchResult.RateLimited`: do NOT mark.
- On `AadeFetchResult.Success`: call `business.ClearAadeSyncFailure()` BEFORE the existing save (mark advancement etc.). If the business was previously broken and is now working, we want to clear that state.

The principle: only persistent auth-equivalent failures should mark the connection as broken. Transient network/server errors should not.

### Task 8: Hangfire job for 24-hour email notification

Create src/Roivo.Web/Infrastructure/Jobs/AadeFailureNotificationJob.cs (or follow the existing job folder pattern in the project):

```csharp
public sealed class AadeFailureNotificationJob
{
    private readonly IBusinessRepository _businesses;
    private readonly IEmailSender _emailSender;
    private readonly ILogger<AadeFailureNotificationJob> _logger;
    
    public AadeFailureNotificationJob(
        IBusinessRepository businesses,
        IEmailSender emailSender,
        ILogger<AadeFailureNotificationJob> logger)
    {
        ArgumentNullException.ThrowIfNull(businesses);
        ArgumentNullException.ThrowIfNull(emailSender);
        ArgumentNullException.ThrowIfNull(logger);
        _businesses = businesses;
        _emailSender = emailSender;
        _logger = logger;
    }
    
    public async Task ExecuteAsync(CancellationToken cancellationToken = default)
    {
        var threshold = DateTime.UtcNow.AddHours(-24);
        
        // Find businesses that:
        // 1. Have an active AADE failure
        // 2. Failure started >24 hours ago
        // 3. Haven't been emailed yet (AadeFailureEmailSentAt is null)
        var businessesToNotify = await _businesses
            .ListWithExpiredAadeFailureAsync(threshold, cancellationToken)
            .ConfigureAwait(false);
        
        foreach (var business in businessesToNotify)
        {
            // Need owner's email — query through tenant or user relationship
            // (depends on existing pattern; check IBusinessRepository or 
            // ITenantContext for how to get this)
            
            var ownerEmail = await GetOwnerEmailAsync(business, cancellationToken);
            if (string.IsNullOrEmpty(ownerEmail)) continue;
            
            var subject = Aade.FailureEmailSubject;
            var body = string.Format(
                Aade.FailureEmailBody,
                business.Name,
                business.Afm,
                business.AadeLastFailureAt!.Value.ToLocalTime(),
                MapFailureReasonToGreek(business.AadeLastFailureReason),
                "https://roivo.gr/businesses/" + business.Id + "/aade");  // Or env-aware URL
            
            await _emailSender.SendAsync(ownerEmail, subject, body, cancellationToken);
            
            business.RecordAadeFailureEmailSent();
            await _businesses.UpdateAsync(business, cancellationToken);
            
            _logger.LogInformation(
                "Sent AADE failure notification to {Email} for business {BusinessId}",
                ownerEmail, business.Id);
        }
    }
    
    // Implementation of MapFailureReasonToGreek and GetOwnerEmailAsync 
    // follows existing patterns in the codebase.
}
```

The repository method `ListWithExpiredAadeFailureAsync` is a new addition to IBusinessRepository:

```csharp
Task<IReadOnlyList<Business>> ListWithExpiredAadeFailureAsync(
    DateTime threshold, 
    CancellationToken cancellationToken = default);
```

Implementation queries: businesses where `HasAadeFailure && AadeLastFailureAt < threshold && AadeFailureEmailSentAt IS NULL`.
