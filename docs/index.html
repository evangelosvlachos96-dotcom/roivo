Bank data and tax data on one screen, reconciled for you.

Roivo is cashflow intelligence for Greek small businesses and their accountants. It connects PSD2 open banking with the myDATA tax platform to automate reconciliation, forecast cashflow 90 days ahead and warn about upcoming tax obligations. .NET 10, Blazor Server, PostgreSQL. Pre-launch; this repository is a public portfolio snapshot of a product developed privately.

Start in four steps

Prerequisites: .NET 10 SDK, Visual Studio 2022 17.12+ or Rider 2025.1+, and PostgreSQL 16 — either installed natively or via Docker.

1 · Postgres

docker compose up -d from the repo root. pgAdmin comes up at localhost:5050. Or install PostgreSQL 16 natively and create a roivo role and database.

2 · Open the solution

Open Roivo.slnx and set Roivo.Web as the startup project.

3 · Apply migrations

Package Manager Console, default project Roivo.Infrastructure: Update-Database -StartupProject Roivo.Web.

4 · Press F5

The app runs at https://localhost:7027 or the port shown in the console.

What it does

Every screen is scoped to a tenant. The user interface is in Greek.

Businesses

Create, rename and deactivate the businesses a tenant manages. Permission rules — who may create, deactivate or edit a tax number — are pure functions in the domain layer.

myDATA sync

Connect a business to the AADE myDATA platform with encrypted credentials. Sync invoices on demand or nightly; a daily job emails the tenant when a sync has been failing for 24 hours.

Invoices

A paged, per-business view over invoices and income-book entries, queried with a single raw-SQL union.

Cashflow

A cashflow page fed by the synced data. The 90-day forecast and PSD2 banking connection are the next milestones (M5 and M7) and are scaffolded, not built.

Accounts

ASP.NET Core Identity with confirmed-email login, lockout, password reset, and tenant claims baked into the auth cookie. OpenIddict is wired in for token issuance to API clients.

Audit

Every login, business change and AADE action writes an audit row. Action codes are grouped by domain and never renumbered.

How it is put together

Layered, with the domain at the bottom. Lower layers never reference higher ones.

  1. Multi-tenancy is a global query filter. The DbContext walks every ITenantScoped entity and installs TenantId == CurrentTenantId; the tenant comes from claims on the auth cookie.
  2. Handlers follow one shape. Null-guard → permission → load → validate → mutate → save → audit → return. Results are discriminated-union records, not exceptions.
  3. Entities enforce their own invariants. Private setters, factory methods, and named mutations such as Rename, ChangeAfm, RecordAadeSyncFailure.
  4. Background work runs in Hangfire. Nightly AADE sync, single-business sync, and the 09:00 Athens failure notification.

Documented in docs/architecture.md (the code map), docs/FLOWS.md (three end-to-end walkthroughs with breakpoints), and docs/CODING_STANDARDS.md. Tests cover the domain, application handlers with fakes, and the infrastructure notification job.
